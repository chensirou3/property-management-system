## 2. 已交付能力

### 2.1 主档、批次与读数连续性

- `/archives/meters` 已从通用 CRUD 切换为专用计量工作台，展示资产、父表、类型/级别、量程、倍率、损耗、末次审核读数、状态，并保留新增和按版本编辑入口；
- 批次必须带 `Idempotency-Key` 和请求哈希：同键同请求返回原批次，同键不同请求返回 `IDEMPOTENCY_REQUEST_CONFLICT`，批次号重复也不会静默新建；
- 读数时间必须属于批次账期，且新账期严格晚于该表最后审核账期；上期数留空时自动承接最后审核止码；
- 同批同表同来源同读数安全重放，不同读数返回冲突；空批次不能审核；
- 用量采用固定快照公式：`raw = current - previous`，`adjusted = raw × multiplier × (1 + lossRate)`，`billable = adjusted + correction + allocatedShare`；
- 上期不一致、超量程和人工修正分别标记 `PREVIOUS_MISMATCH`、`RANGE_EXCEEDED`、`MANUAL_CORRECTION`；异常未复核时审核被阻断；
- 复核使用乐观版本、经办人、时间和理由，只确认异常，不覆盖原始读数和原计算快照；审核后读数、批次汇总数和聚合 SHA-256 一起冻结。

### 2.2 公摊、IoT 与换表证据

- 公摊规则与不可变版本分离，按批次账期选择有效版本；试算返回版本号、总面积、逐资产依据和分配用量；
- 应用公摊时写入 `meter_share_result` 的策略版本、输入快照与 SHA-256，同时重算草稿读数；相同规则/批次/资产重放，参数变化返回冲突；
- 当前面积比例规则始终返回 `assumptionRule=true`，页面明确显示“合成假设口径”；
- IoT 模拟器通过 Inbox 保存适配器编码、来源引用、原始负载、读数时间、模拟标志和 SHA-256；重复入站标记 `REPLAYED`，不会重复产生读数；
- 换表要求旧表止码等于最后审核读数，新起码不超过量程；一次事务中把旧表置为 `REPLACED`、创建新表、保存新旧版本/读数/原因/经办和快照校验值；
- 换表要求 `Idempotency-Key`，返回可追踪 `evidenceNo`；同键异请求拒绝，历史旧表和凭证不删除。

### 2.3 计量应收与阶段边界

- 只有 `APPROVED` 批次可以生成计量应收；必须命中当前账期有效的 `METER_USAGE` 标准版本和仪表分配；
- 金额按计费用量、单价、分配系数、定义精度/舍入及最小/最大值计算；每条读数由 `(source_type='METER_READING', source_id)` 保证最多生成一个账单明细；
- 账单明细保存原始读数快照、原 SHA-256、费用定义/标准/版本/分配、公摊版本、公式与金额输入，后续主档或规则变化不会改写历史账单；
- 生成后自动记录读数数 COUNT、计费用量 USAGE、账单金额 AMOUNT 三项源值、目标值、差异与状态；本阶段三项均为 `MATCHED`；
- G5 通用周期应收明确排除 `calculation_basis='METER_USAGE'`。计量费用只能经 G7“审核读数 → 计量应收”路径进入账单，避免未审核用量被普通批处理误计费。
