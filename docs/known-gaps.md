# 已知差距与外部资料

以下内容不会阻塞本地可运行复刻版，但在取得业务资料并完成对账前不能声明生产等价：

- 真实费用公式、舍入、生效和失效口径；
- 期初欠费、历史账单、预收、押金和退款对账；
- 日结、收缴率和清欠率定义；
- 总分表、公摊、换表和异常读数真实样本；
- 微信/支付宝/银行支付通道；
- 数电票/税控通道；
- 真实仪表和 IoT 厂商协议；
- 票据样式、编号和套打规则。

对应能力在工程中使用策略接口、模拟实现和功能标记，后续可替换而不改页面领域模型。

## 当前实现边界

- 基础档案、菜单、布局、查询、费用配置和本地应收闭环可直接验收。
- 收款、开票和 IoT 是确定性模拟通道，页面和审计快照均明确标记模拟。
- 面积比例公摊和 `billableUsage × unitPrice` 是演示假设规则，不能直接作为生产收费依据。
- 当前没有真实历史迁移、真实住户、真实票据模板或真实第三方密钥。
- Docker Compose 已完成 API/Web 镜像重建，API、Web、MySQL、Redis 均可启动，API 健康检查通过。
- API 已按 ADR-007 迁移到 Spring Boot 3.5.16，并完成 Jakarta、Spring Security 6、springdoc 2.9、Flyway/MySQL、OpenAPI 和端到端兼容验证。
- G1 的企业组织权限生命周期、G2 的 49 页验收体系、G3 的基础档案纵向闭环、G4 的迁移中心、G5 的费用配置与应收以及 G6 的收银与不可变账务已经通过本地门禁。
- G3 使用真实项目内主数据与关系 API，具备资产树、客户时间线、关系起止、产权变更、停用保护、六类 CSV 模板和无写入预校验；主项目有效 359 房屋、250 车位、403 客户、403 客户资产关系均为确定性合成数据。
- 目标系统目前只提供可审计的聚合规模和界面/行为证据，没有取得获准导出的目标逐行业务数据；本工程没有通过抓取或手工复制把真实住户行写入开发库。
- G2 中由 `CapabilityWorkspaceView` 承载的页面使用明确标识的合成/脱敏结构演练数据；这不是目标系统真实业务行，也不代表对应页面已达到 L2/L3。
- G4 已支持最多 500 行 JSON、五层校验、部分错误隔离、管理员审批、受控生产写入、数量/关系/面积对账和本批新增对象回滚；首轮验收使用 32 条合格 + 1 条错误的确定性合成样本，不是获授权的目标站真实历史数据。
- G5 已支持费用定义的会计/税务边界、标准版本、资产/仪表分配预览与取消、四种计算基础、精度/舍入/上下限、周期与临时应收、异步任务、幂等请求哈希、不可变账单快照和三项自动对账；这些能力使用合成规则和合成账单验证，不能替代业务方对真实收费口径、税率和会计科目的签字确认。
- G6 已支持收银班次、部分/组合收款、三种本地渠道、并发确认、预收/押金守恒、调账审批、票据号段、收据/发票换开与红冲、日结锁定和七项自动对账；它不包含真实商户、税控、银行回单、法定日结口径或历史期初账签字。
- 正式历史迁移仍缺数据所有方批准的导出包、字段映射签字、源系统版本、加密对象存储/大文件分片、断点续跑、恢复窗口和财务期初对账；取得资料前不能声明生产迁移完成。
- 49 页当前图片是本工程的防回退基线，不是目标站逐像素相似度结论；各领域在 G7—G9 纵向重构时仍需按验收卡、目标证据和业务状态持续更新。
