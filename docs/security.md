# 安全设计与检查

## 已实施控制

- BCrypt cost 12 保存密码；JWT 密钥必须由环境变量提供且长度至少 32 字符。
- 新密码至少 12 位并包含大小写字母、数字和符号，不能包含完整账号名，也不能与当前密码相同。
- IAM 新建账号首次登录必须改密；首次改密前服务端只允许读取本人信息、改密或撤销会话，不能绕过前端访问业务 API。
- JWT 包含角色、权限、项目范围和会话版本；账号、密码或角色权限变化会递增服务端会话版本，使旧令牌即时失效。
- 登录失败按账号哈希和来源 IP 哈希进行窗口计数和临时锁定；成功、失败、限流均写审计，但不保存原始账号或 IP。
- 后端每个业务入口再次校验权限和 `communityId`；`iam:read` 与 `iam:write` 在页面按钮和服务端分别控制。
- 启用账号的人员、企业角色和项目范围必须属于同一企业；停用角色/组织/岗位/人员前检查启用引用，避免通过错配或悬挂授权绕过边界。
- 会话令牌仅放在 `sessionStorage`，不写入 URL、日志或持久本地筛选条件。
- CORS 仅允许本地开发源；API 无服务端会话，CSRF 面收窄。
- Nginx/API 返回 `nosniff`、拒绝 frame、无 referrer、Permissions Policy；生产 Web 增加 CSP。
- 列表排序字段和资源名使用后端白名单，SQL 参数全部绑定。
- 乐观锁防止静默覆盖；账单和计量来源使用数据库唯一/检查约束。
- 财务写接口使用幂等键和规范化请求 SHA-256；同键不同请求拒绝，成功流水只允许关联冲正。
- 支付确认锁定订单/账单并由数据库唯一键约束每订单一条成功流水；并发重复回调只返回既有结果。
- 收据使用受控号段，收据/发票最终 JSON 保存 SHA-256；换开、作废、红冲保留原对象引用和操作原因。
- 调账需要独立申请/审批、乐观版本和审计；日结锁定后拒绝直接冲正，现金交班保存实盘差异。
- 七项财务对账覆盖账单、支付分摊、预收、押金、日结、收据和发票，持久验收库当前全部为 0 差异。
- 抄表批次和换表必须提供幂等键并保存请求 SHA-256；同键不同内容拒绝，读数唯一键、账期顺序和审核状态防止重复/越期计费。
- 异常读数按乐观版本复核并保留原输入；审核后批次/读数冻结，计量账单引用原读数 JSON 与 SHA-256，不允许通过主档或规则修改回写历史。
- IoT 模拟数据先进入 Inbox，保留适配器、来源引用、模拟标志、原负载和 SHA-256；公摊和换表分别保存策略版本/新旧表版本和不可变事件。
- 通用应收不读取 `METER_USAGE` 分配；计量类应收仅允许从已审核批次生成，并以 COUNT/USAGE/AMOUNT 三项对账持续检查源—账单一致性。
- 22 个报表只允许服务端固定查询分支、绑定参数和定义字段白名单；任意 SQL、表名、排序表达式和未授权列不会从请求透传到数据库。
- 报表目录、查询、任务列表、任务详情和制品下载分别按财务/报表/通知/发票/银行/房产领域权限检查；任务 ID 不作为访问授权，有限账号不能借导出任务越权读取其他领域数据。
- 报表默认对客户姓名脱敏，查询响应附规范化筛选与结果的 SHA-256；异步导出保存水印、选择列、制品校验和和状态事件，CSV 单元格继续防公式注入。
- 批量收据打印冻结模板版本和逐收据快照/校验和；成功后只追加打印次数和最后打印时间，不改写收据原快照。
- 通知表由数据库约束只允许 `*_SIMULATOR` 且 `simulated=true`；接收人脱敏，正文快照和 SHA-256 留痕，当前运行库真实通知通道调用为 0。
- 费用定义、标准、分配和应收任务分别要求 `fee:read`/`fee:write`，每个接口重验项目范围；定义和标准的跨项目引用由复合外键拒绝。
- 应收任务同时保存 `Idempotency-Key` 和规范化请求 SHA-256；相同键不能承载不同请求，避免调用方误用键时静默返回错误业务结果。
- 周期账单生成键由数据库唯一约束保护；定义精度、舍入、税务、标准版本、分配和公式完整写入账单快照及 SHA-256，配置修改不能改写既有账单。
- 批量分配先预览，ACTIVE 生效区间重叠由服务校验和数据库唯一键共同限制；取消只截断有效期并记录原因，不删除历史配置。
- 迁移中心分别要求 `migration:read/import/write/export`；项目范围在每个批次 API 重验，审批与回滚额外要求 `PLATFORM_ADMIN`，写入使用批次版本锁。
- 迁移只接受受控资源和服务端参数绑定，不接受数据库连接串、明文数据库密码、任意表名或 SQL；回滚凭证只向具备写权限的登录人返回并使用常量时间比较。
- 来源 SHA-256、逐行 SHA-256、映射版本、审核人、状态事件、生产变更和回滚原因持久化；错误行不会进入生产层。
- 日志和错误不返回堆栈、密码、JWT、数据库连接秘密或原始个人信息。
- 前端 `npm audit` 当前为 0 漏洞；Axios、ECharts、Vite、Vitest 和 Happy DOM 已升级到修复版本。

## 上线前仍需外部完成

- 使用正式秘密管理器、TLS 终止、WAF/限流、集中日志和告警。
- 本地 bootstrap 管理员的初始密码轮换、生产 MFA、边缘 WAF/分布式限流、集中安全告警。
- 数据库账号最小权限、备份加密、恢复演练和保留策略。
- 真实支付/发票/IoT 接入前做供应商签名、重放防护、回调验签和独立渗透测试。
- 由设备与业务负责人确认真实表号映射、总分表拓扑、量程/回零/补传、损耗、公摊、换表和异常复核规则；当前 IoT Inbox 和假设公式不能直接连接生产设备。
- 对真实住户数据制定分类分级、脱敏、导出审批和数据保留/删除流程。
- 由财务、税务和业务负责人签字确认真实费用科目、税率、精度、舍入、生效边界、上下限和临时费用授权；当前合成配置不能直接上线。
- 由财务/审计负责人对 22 个报表的金标准账期、公式、时间/状态口径、容差、法定属性和导出模板签字；真实通知、银行、税控接入前另做供应商验签、重放和投递回执验收。

本仓库只含合成数据和示例变量，不包含目标站账号、Cookie、令牌或真实住户资料。
