## 1. 交接结论

当前资产足以在另一台设备上继续开发和本地演示，推荐把新工作目录放在不受 OneDrive 同步影响的纯英文短路径，例如：

```text
C:\work\qingdao-property
```

完整恢复分为三部分：

1. 复制三个工作目录：复刻工程、目标系统调查资料、物业核心产品源码；
2. 在新设备重新创建 `.env`，安装或启用 Docker、Git、Java、Maven、Node；
3. 在“全新合成数据库”和“保留旧 QA 数据库”之间选择一种数据恢复方式。

推荐默认选择“全新合成数据库”。12 个 Flyway 迁移会自动创建表结构、合成版“优山美地”、具备最小完整档案链的隔离项目“海湾雅居”和迁移治理表，最容易获得干净、可重复的开发环境。只有确实需要保留此前全面测试产生的账单、支付、抄表和审计流水时，才迁移旧 QA 数据库。

## 3. 复刻工程技术架构

```text
浏览器
  │  http://localhost:5174
  ▼
Vue 3 + TypeScript + Element Plus
  │  /api/*（开发时由 Vite 代理；Compose 时由 Nginx 代理）
  ▼
Spring Boot 3.5.16 / Java 17 / REST / JWT / RBAC
  ├─ MySQL 8.0：业务主数据、账务、审计、Flyway 迁移
  ├─ Redis 7.4：运行期基础设施；不是业务真相源
  └─ Adapter：支付、发票、IoT 为模拟实现，Java110 默认禁用
```

### 3.1 前端

- Vue 3.5、TypeScript 5.9、Vite 7；
- Element Plus 2.11、Pinia、Vue Router、Axios、ECharts、Day.js；
- 主要页面：登录、项目看板、通用档案列表、应收工作台、收银台、抄表工作台；
- 导航和通用页面定义主要位于 `src/config/navigation.ts`、`src/config/pageSchemas.ts`；
- API 客户端位于 `src/api/http.ts`，OpenAPI 生成类型位于 `src/api/generated.ts`；
- 单元/组件测试使用 Vitest，端到端测试使用 Playwright 和本机 Chrome。

### 3.2 后端

- Java 17、Spring Boot 3.5.16、Spring Security 6、JDBC、Flyway、Redis；
- 53 个主 Java 文件、11 个测试 Java 文件；
- 模块：
  - `iam`：登录、管理员引导、企业组织、用户、角色和项目范围；
  - `property`：资产树、资产/客户档案、关系时间线、产权变更和导入预校验；
  - `migration`：五层迁移、来源映射、错误隔离、审批、执行、对账和逆序回滚；
  - `common/data`：通用资源目录、分页、排序、查询和软停用；
  - `fee`：费用定义、标准、分配、应收试算和账单生成；
  - `finance`：收款、分摊、冲正、预收、押金、收据和发票模拟；
  - `meter`：抄表批次、读数、IoT 导入、公摊、审核、换表和计量收费；
  - `dashboard`：项目统计；
  - `adapter`：支付、发票、IoT 和 Java110 的端口及模拟实现；
  - `common/audit`：审计记录；
  - `security`：JWT、RBAC、请求认证和 CORS。

## 5. 迁移前在旧设备上的操作

### 5.1 冻结写入并确认文件已在本地

当前工作区已位于本机桌面，不再使用早期 OneDrive 路径。迁移前仍应冻结写入，并确认目录不是仅联机占位文件：

1. 用 `git status --short` 记录复刻工程工作树状态和最后提交；
2. 确认没有云盘占位文件、断开的重解析点或未落盘下载；
3. 关闭 IDE、终端、开发服务器和可能写入目录的进程。

不要在 OneDrive 尚未完全下载时直接拔盘或打包，否则可能只复制占位符。

### 5.2 选择数据路线

#### 路线 A：全新合成数据库（推荐）

不迁移 Docker 卷和 SQL。新设备首次启动时由 Flyway 创建干净数据库。此前全面测试写入的 QA 流水不会保留。

#### 路线 B：保留旧 QA 数据库

旧设备先启动 Docker Desktop，然后确认容器和数据库：

```powershell
docker ps -a --format "table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}"
docker volume ls
```

此前全面测试使用的数据库名为：

```text
pms3_replica_qa_20260730
```

此前常见的 MySQL 容器名为 `pms3-replica-mysql-1`。名称必须以 `docker ps -a` 的实际输出为准，不要盲目照抄。

逻辑备份优先于直接复制 Docker 卷。下面的命令利用容器内部已有的 `MYSQL_ROOT_PASSWORD`，不会把密码写入命令历史。先创建一个不位于源码目录内的交接文件夹：

```powershell
$handoffDir = 'C:\handoff\qingdao-property-20260823'
New-Item -ItemType Directory -Path $handoffDir -Force
docker start pms3-replica-mysql-1
docker exec pms3-replica-mysql-1 sh -lc 'exec mysqldump --single-transaction --routines --triggers --events --set-gtid-purged=OFF -uroot -p"$MYSQL_ROOT_PASSWORD" pms3_replica_qa_20260730 > /tmp/pms3_qa.sql'
docker cp 'pms3-replica-mysql-1:/tmp/pms3_qa.sql' "$handoffDir\pms3_replica_qa_20260730.sql"
Get-FileHash -Algorithm SHA256 "$handoffDir\pms3_replica_qa_20260730.sql"
```

如果容器内的 `mysqldump` 不支持 `--set-gtid-purged`，删除该参数后重试。导出完成后，可以删除容器里的临时副本：

```powershell
docker exec pms3-replica-mysql-1 rm -f /tmp/pms3_qa.sql
```

Redis 不是业务真相源，迁移时建议不复制 Redis 卷，由新设备重新建立。

重要：恢复旧数据库时，`.env` 中新设置的 `PMS_BOOTSTRAP_ADMIN_PASSWORD` 不会覆盖数据库里已经存在的管理员密码哈希。旧 QA 管理员密码必须通过密码管理器单独交接；如果没有该密码，优先使用全新数据库，不要手工猜测或直接替换哈希。

### 5.3 打包源码和资料

推荐使用外接 NTFS 磁盘直接复制整个 `青岛物业。`，或者使用 7-Zip。必须保留隐藏的 `.git` 目录。

不要使用 PowerShell `Compress-Archive` 打包上游源码，因为它可能忽略 Windows 隐藏文件，从而丢失 `.git` 历史。

如网络可用且不需要携带构建缓存，可排除第 2.1 节所列的可再生产物。为降低遗漏风险，第一次交接建议完整复制，然后在新设备验证成功后再清理缓存。

建议把以下三类资料分开保存：

1. `source-and-docs`：三个顶层目录；
2. `database-backup`：可选的 SQL dump；
3. `secrets`：管理员密码、第三方密钥等，只通过密码管理器或加密介质传输，不放入源码压缩包。

### 5.4 为上游 Git 历史做第二份保险

直接复制 `.git` 之外，可为每个非空上游仓库创建 bundle：

```powershell
$sourceRoot = 'C:\Users\67580\Desktop\青岛物业。\物业核心产品源码'
$bundleRoot = 'C:\handoff\qingdao-property-20260823\git-bundles'
New-Item -ItemType Directory -Path $bundleRoot -Force

git -C "$sourceRoot\MicroCommunity" bundle create "$bundleRoot\MicroCommunity.bundle" --all
git -C "$sourceRoot\MicroCommunityWeb" bundle create "$bundleRoot\MicroCommunityWeb.bundle" --all
git -C "$sourceRoot\WechatOwnerService" bundle create "$bundleRoot\WechatOwnerService.bundle" --all
git -C "$sourceRoot\PropertyApp" bundle create "$bundleRoot\PropertyApp.bundle" --all
git -C "$sourceRoot\MicroCommunityIot" bundle create "$bundleRoot\MicroCommunityIot.bundle" --all

Get-ChildItem -LiteralPath $bundleRoot -Filter *.bundle | ForEach-Object {
    git bundle verify $_.FullName
    Get-FileHash -Algorithm SHA256 $_.FullName
}
```

空的 `MicroCommunityParkingAgent` 没有可打包提交，保留目录和远端信息即可。

6. 409 通常表示乐观锁或幂等冲突，400 表示字段或业务规则错误。
