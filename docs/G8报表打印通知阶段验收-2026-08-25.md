## 1. 阶段结论

G8 的内部退出条件已满足，可以进入 G9 外部适配、安全、可观测和部署。22 个目标查询页面均已连接固定服务端读模型，具备项目隔离、领域权限、字段白名单、筛选/分页、行粒度、公式说明、固定算例、汇总、钻取提示、数据源边界和查询 SHA-256；大导出、收据打印和账单通知分别形成可持久化任务、制品/快照、校验和与状态证据，看板收缴指标与报表使用同一查询源。

该结论只适用于本工程的确定性合成账务、内部台账和模拟通道。尚未取得经授权的目标系统金标准账期、财务/审计口径签字、正式 Excel/PDF/票据模板或真实短信、微信、邮件、银行和税控通道，因此不得把 G8 描述为生产报表、法定报表、正式套打或真实消息投递已经验收。

## 2. 已交付能力

### 2.1 22 个受治理报表

- `report_definition` 固定唯一 `report_code` 与页面路径，并保存标题、行粒度、公式说明/JSON、字段白名单和固定算例；
- 查询引擎只执行代码内 22 个显式 SQL/模拟分支和绑定参数，不接受请求提供的 SQL、表名或任意列；
- 每次查询在服务端重验 `communityId`、调用者项目范围和报表所属领域的读取权限；客户姓名默认脱敏；
- 响应统一返回 `reportCode`、`rowGrain`、`formulaNote`、`fixedSample`、`summary`、`drillDown`、`productionConnected`、`integrationMode`、`queryChecksum`、`durationMs`、分页和行数据；
- 选择列只能取定义白名单；V18 只为批量打印报表追加受控 `receiptId` 操作键，UI 可选择收据但不会开放任意数据库字段；
- 看板财务指标标记 `metricSource=COLLECTION_RATE`，金额直接复用收缴率报表结果，不维护第二套统计口径；
- 账单通知、提醒、发票统计和银行信托分别标记内部账本/通知模拟器/发票模拟器/银行信托模拟器，未授权外部数据不会伪装生产连接。

22 个编码为：

`TRANSACTION_SUMMARY`、`TRANSACTION_DETAILS`、`RECEIPT_BATCH_PRINT`、`PAYMENTS`、`ARREARS`、`BILL_NOTIFICATIONS`、`BILLS`、`COLLECTION_RATE`、`ARREARS_CLEARANCE_RATE`、`COMPREHENSIVE_QUERY`、`COLLECTION_CLEARANCE_SUMMARY`、`CHARGE_DETAILS`、`DISCOUNT_DETAILS`、`PREPAYMENTS`、`OWNERSHIP_TRANSFERS`、`REMINDERS`、`FEE_STATUS`、`INVOICE_STATISTICS`、`DEPOSITS`、`DAILY_SETTLEMENT_DETAILS`、`ADJUSTMENTS`、`BANK_TRUST`。

### 2.2 异步导出与制品证据

- CSV、XLSX、PDF 和 PRINT 统一通过 `report_export_job` 创建 QUEUED 任务，受控执行器转为 RUNNING 后写入 SUCCEEDED/FAILED；
- 请求保存 `Idempotency-Key`、规范化请求 SHA-256、筛选、选择列、格式和水印；同键同请求重放，同键不同请求冲突；
- 成功任务保存行数、文件名、MIME、制品 BLOB、SHA-256、开始/完成时间；`report_export_event` 保存 QUEUED/STARTED/SUCCEEDED/FAILED/DOWNLOADED 轨迹和事件校验和；
- CSV 单元格防公式注入；XLSX 浏览器验收核对 ZIP 文件头和下载字节 SHA-256；
- 任务列表只返回调用者可读报表域；任务详情要求读取权限，制品下载重新要求所属域导出权限，任务 ID 不构成授权。

### 2.3 批量收据打印

- 打印任务只接受项目内已签发收据和 PDF/PRINT 格式，保存请求哈希、模板版本、水印、项目、操作者和任务终态；
- 每个 `receipt_print_item` 固定保存收据号、顺序、完整收据快照和 SHA-256；任务项数由数据库检查且与明细数量对账；
- 成功后生成制品 SHA-256，并在原收据上追加 `print_count` 和 `last_printed_at`；重复打印增加次数，不覆盖收据签发、换开或作废历史；
- 页面 41 从报表结果选择受控 `receiptId`，创建任务后可看到模板、项数、状态、文件和校验和。

### 2.4 账单通知模拟器

- 通知批次只允许 `SMS_SIMULATOR`、`WECHAT_SIMULATOR`、`EMAIL_SIMULATOR`，数据库强制 `simulated=true`；
- 选择账单、账期、正文模板、请求哈希、成功/失败数和完成时间均持久化；
- 消息保存账单/客户引用、脱敏接收人、正文快照、内容 SHA-256、`SENT_SIMULATED` 状态和唯一模拟引用；
- 页面和 API 明确提示未调用真实短信、微信或邮件通道；持久运行库真实通知渠道和非模拟消息均为 0。

## 3. 页面与兼容业务操作

22 个目录路径均由 `ReportingWorkbenchView` 承载，覆盖页面 13—16、27—36 和 41—48。工作台支持筛选、保存/恢复筛选、刷新、服务端分页/页容量、动态白名单列、汇总、异步导出、任务轮询/下载，以及打印或通知专用操作。

页面 13/14/15/16/27/28/29/34/36 同时存在 G6 财务操作能力，因此保留“统计视图 / 业务处理”双模式。G8 默认显示受治理报表，进入业务处理后仍使用原 `FinancialOperationsView`。完整 G6 浏览器生命周期已改为显式进入业务处理层，并继续核对原应收/调整、冲正反向流水和日结锁定；这证明 G8 没有用报表页面替代或破坏原账务能力。
