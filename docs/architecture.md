# 架构决策

## ADR-001：独立工程

复刻工程不修改 `物业核心产品源码`。Java110 用作领域和适配参考，新代码、迁移和测试均保存在本目录。

## ADR-002：模块化单体

第一版使用一个 Spring Boot 进程，按 `iam`、`property`、`fee`、`cashier`、`meter`、`adapter` 分包。跨模块通过应用服务和领域事件协作，避免初期微服务部署成本。

## ADR-003：稳定 API

前端只依赖 `/api/v1`。目标站相对 `/list` 接口和 Java110 `serviceCode` 不进入页面代码；兼容逻辑放在 adapter 层。

## ADR-004：财务不可变

成功账单和交易不物理删除。退款、冲正、预收抵扣和押金退还使用关联反向流水。金额使用 `BigDecimal` 和数据库 Decimal。

## ADR-005：外部通道默认模拟

支付、发票、IoT 和 Java110 都定义端口接口。开发环境启用确定性模拟实现，页面必须展示“模拟通道”，不得描述为生产能力。

## ADR-006：合成数据

种子数据只复现“优山美地”的规模、字段覆盖和关系统计。个人信息、原始 ID、房号、金额和业务凭据全部重新生成。

## ADR-007：Spring Boot 受支持版本

API 已从 Spring Boot 2.7.18 迁移到 Spring Boot 3.5.16，保持 Java 17，并完成 Jakarta、Spring Security 6、springdoc 2.9 与 Flyway/MySQL 兼容迁移。详细决策、验收和回滚见 [`adr/ADR-007-spring-boot-supported-version.md`](adr/ADR-007-spring-boot-supported-version.md)。

## ADR-008：统一资产与不可变关系事件

房屋、车位和公共区域统一使用 `asset` 聚合，类型专属字段放入一对一明细表；网格—楼栋—单元—资产通过带 `community_id` 的复合外键保证项目内层级。客户资产关系使用有效期、状态和版本表达权属/租住变化，不覆盖历史；关系起止和产权转移另写入 `property_relation_event`，请求键保证幂等。档案停用使用引用保护和软状态，不通过级联删除清除业务历史。

## ADR-009：受治理的五层迁移与反向变更日志

迁移中心以批次为边界，把来源证据依次分为 Raw、Quarantine、Canonical、Staging 和 Production。来源 SHA-256 与映射版本形成重放键；Raw 保留原始 JSON 和逐行校验和，错误行与合格行物理分层。生产写入必须经过项目范围、权限、平台管理员审批和乐观版本校验。首批只允许 PROJECT、BUILDING、ROOM ASSET、CUSTOMER、RELATION 白名单资源，不执行任意表名或 SQL。每个新建对象及房屋类型明细写入反向变更日志，回滚按执行顺序倒序删除本批对象，同时保留 Raw、隔离错误、映射、对账、事件与审计证据。

## ADR-010：费用配置按生效期版本化，应收按快照异步落账

费用定义保存会计科目、税务分类、税率、币种、小数位和舍入方式；费用标准与不可变版本分离，版本和分配都使用闭区间生效日并拒绝同一对象上的重叠有效区间。分配以资产或仪表为目标，批量写入前必须预览命中对象；取消通过截断有效期保留历史，不删除已经用于账单的配置。

周期和临时应收都先执行无写入预览，再把完整请求、配置快照及 SHA-256 放入 `receivable_generation_job`。任务在受控异步执行器中落账，逐行状态、错误和三项配置—应收—账单对账分别持久化。`Idempotency-Key` 与规范化请求哈希共同决定重放：同键同请求返回原任务，同键不同请求返回冲突。周期账单由项目、资产和账期形成数据库唯一键；账单与明细保存费用定义、标准版本、分配、公式、精度和舍入快照，因此后续配置修改不会改写历史账单。临时应收只允许显式开启 `temporary_allowed` 的费用定义，和周期规则保持独立边界。

## ADR-011：收银确认唯一，账务变更追加证据，日结后锁定

支付订单保存规范化请求 JSON、SHA-256 和幂等键；账单行锁防止超额分配，数据库唯一成功键保证同一订单的并发回调只产生一条成功 PAYMENT 和一张收据。收银现金另以班次为边界保存备用金、现金净变动、实盘值、差异、交班人和锁定状态。

账单同时保存原应收、合法调整、总额、已收和未收，金额变化只能由支付分摊、关联冲正或经审批调账产生。预收抵扣冲正恢复账户余额；押金退款不得超过原账户余额；收据换开/作废和发票换开/红冲均追加关联记录及最终 JSON 快照 SHA-256。日结按 UTC 自然日汇总成功交易和渠道快照，锁定时绑定交易并锁定相关账单；锁定范围内禁止直接冲正。七项对账读模型持续核验账单、支付分摊、预收、押金、日结以及收据/发票校验和。

## ADR-012：计量先冻结读数证据，再进入独立计费边界

仪表读数不是普通可覆盖字段。批次先以请求键/哈希治理建档，读数按审核历史自动承接上期止码，保存账期、来源、倍率、损耗、修正、公摊和完整公式快照；跨期、倒序和异常未复核会阻断审核。审核把读数状态、批次计数及聚合 SHA-256 一起冻结。IoT 通过 Inbox 保存原负载，换表保存新旧版本与连续读数凭证，公摊保存有效策略版本，所有路径都追加 `meter_event`，不通过覆盖或删除清除历史。

计量应收只能从已审核批次产生，并必须命中账期有效的 `METER_USAGE` 标准版本和仪表分配；G5 通用周期应收明确排除此计算基础。账单明细嵌入原读数 JSON、原 SHA-256、标准/分配/公摊版本和金额输入，随后用 COUNT、USAGE、AMOUNT 三项读模型核对计量源与账单。这样费用配置与账务模块消费已冻结的计量事实，而不会提前读取草稿用量或在规则变化后重算历史。当前面积公摊、损耗和 IoT 均标记为合成假设/模拟实现，真实策略替换必须新增版本而不能改写旧快照。

## ADR-013：报表定义固定、制品异步留痕、外部通知默认模拟

22 个查询页面不是任意 SQL 工作台。每个报表在 `report_definition` 中固定唯一编码、页面路径、行粒度、公式说明、字段白名单和固定算例；执行器只允许代码内显式查询分支和绑定参数。查询响应附带筛选规范化后的 SHA-256、汇总与钻取提示，项目范围和领域权限在服务端重复检查。看板指标调用同一报表查询源，避免另写一套统计 SQL 形成口径漂移。

大导出统一创建 `report_export_job`，后台生成 CSV/XLSX/PDF/PRINT 制品并保存请求哈希、筛选、选择列、水印、状态事件、行数、MIME、BLOB 和 SHA-256。下载不是持有任务 ID 即可访问，仍需报表所属领域的导出权限。批量收据打印另冻结模板版本、顺序和逐收据快照，成功后追加打印次数，不改写原收据业务事实。

通知批次强制使用 `*_SIMULATOR` 渠道和 `simulated=true` 数据库约束，保存脱敏接收人、正文快照、校验和与模拟引用，不连接真实短信、微信或邮件。发票统计、银行信托等尚未授权的外部来源也明确返回模拟/内部台账模式。将来接入真实服务必须在 G9 增加端口、签名/重放/重试、功能开关和独立验收；不得通过修改既有报表历史或把模拟状态改名为生产状态来接入。
