### 3.3 Playwright 端到端测试

结果：1 通过、1 失败。

- 登录、项目看板、359 套房屋数据：通过；
- 应收、收银页面加载：通过；

失败原因已经定位：测试脚本固定查找 `GOAL-METER-*`，该批次是以前验收时手工生成的数据，不属于 V4 全新数据库种子。全新数据库的抄表批次页面正确显示空状态，但测试错误地依赖旧数据库残留。

这不是仪表页面功能失败，而是 E2E 不可重复。整改方式：测试应在 `beforeAll` 中通过 API 创建自己的批次，或者先断言空状态，再通过页面创建批次；禁止依赖长期数据库残留。

## 7. HTTP 与安全行为

通过项：

- `X-Content-Type-Options: nosniff`；
- `X-Frame-Options: DENY`；
- `Referrer-Policy: no-referrer`；
- 摄像头、麦克风、定位权限策略关闭；
- Web 容器包含 CSP；
- 仅允许本地 5174 Origin，未授权 Origin 被拒绝；
- 合法请求 ID 回写，含空格的不安全 ID 被 UUID 替换；
- 无效 JWT、缺失 JWT 均被拒绝；
- 运行状态接口不返回数据库、Redis 或 JWT 秘密；
- 未发现目标站密码、目标站地址、私钥标记或 AWS 访问密钥样式内容；
- API 和 Web 镜像均使用非 root 用户运行。

发现：缺失或无效 JWT 当前返回 403，而运行文档约定 401，前端响应拦截器也只在 401 时清除会话并跳转登录页。令牌过期时可能停留在业务页面并连续显示 403。需要配置 Spring Security `AuthenticationEntryPoint` 返回统一 JSON 401，并保留授权不足为 403。

当前没有登录限流、失败锁定或验证码策略。若系统暴露到公网，需要在网关或应用侧补充防暴力登录能力。

### 后端

工程使用 Spring Boot 2.7.18。Spring 官方已明确 2.7.18 是 Spring Boot 2.x 开源支持的最后一个版本；继续用于生产将无法获得新的开源安全修复。应规划迁移到当前受支持的 Spring Boot 3.x 版本，并同步处理 `javax.*` 到 `jakarta.*`、Spring Security 配置和依赖兼容性。

参考：<https://spring.io/blog/2023/11/23/spring-boot-2-7-18-available-now/>

本轮没有配置 Java 依赖 CVE 扫描器。生产 CI 应增加 OWASP Dependency-Check、Trivy 或等价能力，并保存 SBOM。

当前版本可以作为：

- UI 和页面复刻基线；
- 基础档案与费用模型联调系统；
