## 2. 外部适配与 fail-closed 边界

- `PAYMENT_SIMULATOR`、`INVOICE_SIMULATOR`、`BANK_TRUST_SIMULATOR`、`IOT_SIMULATOR` 为启用的确定性模拟器；`JAVA110_DISABLED` 为禁用状态；
- 适配器策略保存类型、显示名、模式、启用状态、脱敏端点、凭据状态、是否要求签名、超时、最大尝试次数和退避基线；不会存储或返回真实密钥；
- 配置属性只接受 `simulator` 或 `disabled`。任何未实现的 production 模式、生产端点或绕过字段都会在应用启动时 fail-closed；
- 连接测试记录结果、耗时、请求追踪号和详情 SHA-256；Java110 返回明确禁用证据，不伪造连接成功；
- 页面 39 使用专用 `IntegrationSettingsView`，固定显示“没有任何生产通道”，支持查看五项状态、逐项/全部检测、模拟 Outbox、失败恢复演练、排空模拟事件和查看投递/死信证据；
- 只有平台管理员可制造模拟事件、排空和重放；只读权限只能查看脱敏状态。

## 3. 签名、幂等、重试和租户隔离

回调规范串固定为：

```text
timestamp + "\n" + adapterCode + "\n" + callbackId + "\n" + rawJsonPayload
```

- 使用 HMAC-SHA256、小写十六进制、恒定时间比较和默认 ±300 秒时间窗；缺失/错误签名返回 401；
- `(adapter_code, callback_id)` 唯一。同一编号与同一负载安全重放并递增 `replay_count`；同一编号与不同负载返回 `409 CALLBACK_REPLAY_CONFLICT`；
- Inbox 保存项目、负载 SHA-256、状态、首次/末次接收时间、重放次数和请求追踪号；
- 模拟 Outbox 保存请求哈希、项目和 `simulated=true`。投递最多三次，失败进入死信；重放保留原尝试和死信，只追加证据并在成功后置为 `RESOLVED`；
- 工作台、连接测试、投递尝试、死信、模拟创建和排空均按 `communityId` 重验项目权限；服务端覆盖负载中的项目字段；
- 单笔模拟投递和排空只接受 `aggregate_type=INTEGRATION_SIMULATOR`。集成测试插入真实业务 Outbox 后，模拟投递返回 404，排空后该业务事件仍为 PENDING，证明治理工具不能消费财务/应收业务事件。

## 5. 可观测、安全和部署交付

- ECS 结构化日志记录 method、path、status、durationMs 和 requestId；响应、错误结构、审计和集成证据可按同一 `X-Request-Id` 对齐；

- `deploy/nginx-tls.conf.example` 给出 TLS 1.2/1.3、HSTS、HTTP→HTTPS、登录/回调限流、请求体限制和代理追踪头；配置不依赖宿主的隐式 `proxy_params`；
- `deploy/docker-compose.production.example.yml` 展示 configtree Secret 引用；数据库迁移账号与运行账号的生产拆分要求已写入部署基线；
- API 和 Web Alpine 层执行安全更新；Web 使用 `nginxinc/nginx-unprivileged:1.29-alpine`；MySQL 使用基于 8.4 的加固镜像，移除未使用且带漏洞的 MySQL Shell Python 运行时和 root-only gosu；
- Netty 从 4.1.135.Final 固定到已修复的 4.1.136.Final；Flyway 固定 11.20.3 并在 MySQL 8.4 空库路径验证；
- 健康检查使用 `MYSQL_PWD`/`REDISCLI_AUTH`，秘密不出现在进程参数；应用密钥只从忽略的 `.env` 或生产 Secret 读取。
